# 시설 확장 제안 — 원작 '대기실'에서 가져올 것

> **성격: 제안이다. 아직 결정이 아니다.**
> `gdd-v3.md`와 충돌하면 **v3가 이긴다.** 채택이 확정되면 v3 §4.5에 반영하고 이 문서는 폐기한다.
> 밸런스 수치는 여기 적지 않는다 — `src/game/data/`가 정본이다.
>
> 작성: 2026-08-31. 근거는 원작 웹툰/웹소설 설정(시스템 구조만 참고, 고유명사·아트는 무관).

## 1. 현재 구현 (2026-08-31 실측)

| 축 | 현행 |
|---|---|
| 시설 | 숙소·훈련소·합성소·무기창고 4종, Lv.0~3, **금**으로 강화 (`data/facilities.ts`) |
| 훈련소 | 유휴 exp는 **전투에 안 나간 영웅 전원**에게 자동 지급 |
| 파티 | 1~20층 정원 3 / 21층~ 정원 5, 2군은 로스터 8인 + 21층에서 개방 (`data/party.ts`) |
| 미션 | 6종 — 토벌·생존·수비·호위·탈출·탈취 (`game/mission.ts`) |
| 브리핑 | `BriefScreen`이 이미 **임무 유형과 브리핑 문구를 표시**한다 |
| 거점 화면 | `IsoVillage`(부감도) + `BaseMap`(시설 레벨을 건물 구조로) |

**잉여 영웅의 출구는 현재 '제물' 하나뿐이다.** 이 문서의 제안 A는 그 지점을 겨눈다.

## 2. 원작이 시설물을 쓴 방식 — 셋만 가져온다

1. **층이 곧 계급이다.** 원작의 한 마스터는 "시설 중시형 무과금 라이트 유저"로,
   *층의 계급화를 통해 영웅들의 동기를 자극*했다. 대기실 배치가 1층 훈련생 → 2층 직업층
   → 3층 공격대 → 4층 파티 저택으로 갈려 있고, **승급이 곧 이사**였다.
2. **합성 대신 일을 준다.** 운영 총괄이 세운 원칙 —
   *"게으르지만 않다면 합성 대신 어떠한 일이라도 주는 방식이라 더더욱 믿고 따른다."*
   비전투 영웅이 갈려나가지 않고 교관·요리사·제작·채집으로 배치된다.
3. **층과 층 사이에 준비가 있다.** 34층에서 물자를 얻어 **35층에서 그 자원으로 버프를 걸고**
   보스를 잡는다. 등반이 연속 전투가 아니라 `준비 → 출정`의 반복이다.

## 3. 제안 A — 배치(assignment): 잉여 영웅의 두 번째 출구

**왜.** 지금 남는 영웅의 유일한 용도가 제물이다. 원작의 무게는 *제물과 배치의 대칭*에서
나온다. 갈아 없앨 수도 있고, 일을 줘서 곁에 둘 수도 있어야 선택이 된다.

**규칙(초안)**
- 시설마다 배치 슬롯 N개. 배치된 영웅 수에 비례해 그 시설 효과가 소폭 상승한다.
- 배치 영웅을 출전시키면 **그 층 동안 해당 시설 산출이 멈춘다.** 전투력과 생산의 제로섬.
- 배치 자체는 사망 위험이 없다 — 대신 **성장하지 않는다.**

**반드시 지킬 것 (gdd-v3 §4.5)**
> 훈련소는 전투에 안 나간 영웅만 준다. 참전자와 경쟁시키면 "안 내보내는 게 이득"이 되어
> 퍼머데스의 긴장이 사라진다.

배치 이득이 **출전 성장보다 항상 작아야 한다.** 이 부등식이 깨지면 배치는 최적 전략이 되고,
영웅을 내보내지 않는 게 정답이 되어 이 게임의 축이 무너진다.

**주의 — 훈련소와의 충돌.** 유휴 exp는 지금 대기 영웅 *전원*에게 간다.
"배치자만 받는다"로 바꾸는 것은 **밸런스 변경**이다 (`climb-check.mts` 재측정 필수).
1차에서는 **기존 유휴 exp를 그대로 두고 배치 보너스를 얹는 쪽**을 권한다.

**수치 위치.** `data/facilities.ts`에 `ASSIGN_SLOTS` / `ASSIGN_BONUS`로. 코드에 하드코딩 금지.

## 4. 제안 B — 출정 준비 한 수 (미션 유형 대응)

**왜.** `BriefScreen`이 임무 유형을 이미 보여주는데, 플레이어가 그걸 보고 할 수 있는 일이 없다.
개입(§4.3)이 *전투 중* 판단이라면 이건 *전투 전* 판단이다. 원작의 34→35층 구조가 이것이다.

**규칙(초안)** — 브리핑 화면에서 **금**을 내고 1회 선택. 유형별로 1~2개만.

| 미션 유형 | 준비 한 수 (예) |
|---|---|
| 수비 | 방벽 — 사수 대상 내구 상승 |
| 호위 | 호위 대상 초기 HP 상승 |
| 생존 | 출정 전 부분 회복 (숙소 휴식의 축약형) |
| 토벌 | 파티 초격 1회 (무기창고 레벨에 연동) |
| 탈출·탈취 | 이탈 판정 턴 완화 |

**새 자원을 만들지 않는다.** gdd-v3 §4.2 — 금이 소환·합성·시설·장비 네 곳에서 동시에
요구되는 것이 설계 의도다. 준비 페이즈에 별도 포인트(AP 같은 것)를 두면 그 경쟁이
무력화되고, "쓰면 이득뿐인 무료 손잡이"가 하나 생긴다. **금이 다섯 번째 경쟁자로 들어가는 편이 옳다.**

**시드 재현성 (절대 규칙).** 준비 선택은 *전투 입력*이다. 개입과 같은 경로로 처리한다 —
선택 후 **같은 시드로 전투를 다시 계산**한다. 재생 중인 상태를 직접 수정하는 방식은 금지.

**재측정 의무.** 승률을 통째로 밀어 올린다. `npm run sim` **과** `npx tsx climb-check.mts` 둘 다.

## 5. 제안 C — 층=계급 시각화 (밸런스 무관, 가장 안전)

- 영웅 카드/상세에 **거처**를 표시하고, 승급 시 **이사** 연출을 넣는다.
  등급 차이를 색이 아니라 구조로 표현한다는 규칙(§UI)의 연장선이다.
- `IsoVillage`에 거주 구역을 더한다. **좌표는 `VILLAGE_LOTS` 한 곳에만** 적고,
  라벨 겹침은 눈이 아니라 `iso.test.ts`가 판정한다.
- 승급이 레벨을 1로 리셋해 *직후에 약해지는* 설계(의도된 대가)에
  **눈에 보이는 보상**을 붙여주는 효과가 있다.

## 6. 접은 아이디어 — 왜 접었는지

| 아이디어 | 판단 |
|---|---|
| 회차에 시설 **청사진 계승** | **폐기.** gdd-v3 §7 — 계승은 기록뿐이다. 시설을 물려주면 `sim` 기준선이 회차마다 갈린다 |
| **사기(morale)** 시스템 + 명령 거부 | **보류.** 퍼머데스가 이미 부정 피드백 축이다. 두 번째 전역 손잡이는 검증된 밸런스 표를 통째로 재수렴시킨다. "명령 거부"는 플레이어 입력이 개입 3종이라는 §4.3과도 부딪힌다 |
| 시설 9종 + 자원 3종(원석·식재·공적) 신설 | **폐기.** 금 단일 경쟁 구조(§4.2)를 깬다. 시설은 4종으로 충분하고, 부족한 것은 종류가 아니라 **선택**이었다 |
| 준비 페이즈 전용 **AP** | **폐기.** 위와 같은 이유 — 금으로 대체한다 (제안 B) |

> **세 제안이 전부 끝났다**(A=STEP 48 · B=STEP 49 · C=STEP 50).

## 8. 수용 기준 (Vitest)

- [ ] 배치된 영웅을 출전 편성에 넣으면 해당 시설 산출이 그 층 동안 0이 된다
- [ ] 배치 보너스로 얻는 exp/전력이 **같은 층 출전으로 얻는 것보다 항상 작다** (부등식 테스트)
- [ ] 준비 한 수를 선택해도 **같은 시드 → 같은 `BattleEvent[]`**가 재현된다
- [ ] 금이 부족하면 준비 한 수가 거부되고 상태가 변하지 않는다
- [ ] 준비 한 수는 층 클리어/실패와 무관하게 **그 층에서만** 유효하다
- [ ] 시설 배치 상태가 저장/불러오기를 왕복해도 보존된다
- [ ] 회차 시작 시 시설 레벨과 배치가 **초기화된다** (§6 계승 금지 확인)
