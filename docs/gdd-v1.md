## 1. 컨셉 한 줄

> **뽑기로 얻은 영웅들을 소모하며 던전 100층을 오르는, 죽으면 끝인 가챠 로그라이트.**

일반 가챠 게임과의 결정적 차이 = **영웅의 영구 사망(퍼머데스)**.
캐릭터가 자원이 아니라 "생명"이라는 감각이 이 게임의 유일한 정체성.

---

## 2. 핵심 루프

```
가챠(뽑기) → 파티 편성 → 던전 층 진입 → 전투(자동/반자동)
   → 승리: 경험치·재화·승급석 획득 / 패배: 영웅 영구 사망
   → 층 클리어 → 다음 층 (반복)
```

1회 플레이 = 1런(run). 전멸 시 런 종료, 일부 재화만 계승(메타 프로그레션).

## 3. 시스템 상세

### 3.1 영웅 등급 (★)

| 등급 | 획득처 | 만렙 | 다음 등급 승급 조건 |
|---|---|---|---|
| ★1 | 무료 가챠 | 10 | Lv.10 + 승급석 1 |
| ★2 | 무료 가챠 | 20 | Lv.20 + 승급석 3 |
| ★3 | 무료/유료 | 40 | Lv.40 + 승급석 8 |
| ★4 | 유료 가챠 | 60 | Lv.60 + 승급석 20 |
| ★5 | 유료 가챠 | 80 | Lv.80 + 각성석 1 |
| ★6 | 승급 전용 | 99 | — |

- 승급 시 기본 스탯 계수 상승 + 신규 스킬 1개 해금
- **의도적 언밸런스**: 낮은 등급 승급은 쉽고, 고등급은 급격히 어려움 → 후반 성장 병목이 곧 난이도

### 3.2 가챠

- **무료 가챠**: 12시간 쿨 or 던전 재화 소모. ★1~★3
- **유료 가챠**: 프리미엄 재화. ★3~★5 (천장 60회 = ★5 확정)
- **리세마라 불가 설계**: 계정당 1개, 초기화 시 진행도 소멸 (원작 설정 차용)

확률 예시(무료): ★1 60% / ★2 30% / ★3 10%
유료: ★3 75% / ★4 21% / ★5 4%

### 3.3 던전 100층

- **10층 단위 챕터** (1~10 초원, 11~20 지하수로, …)
- 매 10층 = **보스층**, 매 25층 = **관문(Gate)** — 파티 전원 평균 등급 조건 미달 시 입장 불가
- 층 구성: 일반전 3~5회 → 이벤트/상점 → 보스
- 층 진입 시 **미리보기 제공** (적 구성/속성) → 파티 편성이 실질적 의사결정

### 3.4 전투

- 5인 파티, 턴제 자동전투 + 수동 스킬 발동(액티브 1~2개)
- 속성 상성 5종: 화 → 풍 → 지 → 뇌 → 수 → 화 (1.5배 / 0.7배)
- 역할: 딜러 / 탱커 / 힐러 / 서포터 / 브레이커
- **HP는 층 사이에 자동 회복되지 않음** → 자원 관리가 핵심

### 3.5 퍼머데스 & 계승

- 전투 중 사망한 영웅은 **영구 소멸** (부활 아이템은 초희귀)
- 런 종료 시 계승되는 것:
  - 계정 레벨 / 도감(획득 이력) / 소량의 프리미엄 재화 / 해금된 특성
- 계승되지 않는 것: 보유 영웅, 장비, 던전 진행도

### 3.6 메타 프로그레션 (재도전 동기)

- **도감**: 처음 뽑은 영웅 등록 → 영구 스탯 버프 소량
- **특성 트리**: 누적 층수로 포인트 획득 → 시작 재화 증가, 초기 가챠 횟수 등
- **최고 기록**: 최고 도달 층수 랭킹

## 4. MVP 범위 (1차 목표)

**넣을 것**
- 영웅 12종 (★1~★5), 던전 20층, 전투 시스템, 가챠, 승급, 퍼머데스, 로컬 저장

**빼는 것**
- 장비, PvP, 길드, 결제, 서버 동기화, 애니메이션 이펙트

MVP는 **1인 개발 2~3주** 규모로 잡을 것. 재미 검증 → 확장.

## 5. 기술 스택 제안

| 영역 | 선택 | 비고 |
|---|---|---|
| 프론트 | React + TypeScript + Vite + Tailwind | 기존 표준 스택 그대로 |
| 상태관리 | Zustand | 게임 상태(런 스냅샷) 관리에 적합 |
| 전투 엔진 | 순수 TS 모듈 (`/src/game/`) | **UI와 완전 분리** — 테스트 가능하게 |
| 저장 | IndexedDB (Dexie) | MVP는 로컬 완결 |
| 테스트 | Vitest | 전투 로직 유닛테스트 필수 |
| 백엔드(2차) | Spring Boot + MySQL | 랭킹/계정 동기화 필요해질 때 |

> 게임 엔진(Phaser/Unity)은 불필요. 이 게임은 사실상 **데이터 + 턴 시뮬레이션 + UI**라 웹 스택으로 충분.

## 6. 디렉토리 구조 제안

```
src/
├─ game/                 # 순수 로직 (React 의존 X)
│  ├─ types.ts           # Hero, Enemy, Skill, RunState
│  ├─ data/              # heroes.json, enemies.json, floors.json
│  ├─ gacha.ts           # 뽑기 확률/천장
│  ├─ battle.ts          # 턴 시뮬레이터
│  ├─ progression.ts     # 레벨업/승급
│  └─ run.ts             # 런 생명주기
├─ store/                # Zustand
├─ components/           # UI
├─ screens/              # Home, Gacha, Party, Dungeon, Battle, Result
└─ persistence/          # IndexedDB
```

## 7. Claude Code 작업 순서 (프롬프트 단위)

1. **프로젝트 셋업** — Vite + TS + Tailwind + Vitest, 디렉토리 스캐폴딩
2. **타입 정의** — `game/types.ts` 전체 도메인 모델 확정 ← *여기가 가장 중요*
3. **데이터 시딩** — 영웅 12종, 적 20종, 층 20개 JSON
4. **전투 엔진 + 테스트** — UI 없이 `battle.ts`만. Vitest로 승패 시뮬 100회 돌려 밸런스 확인
5. **가챠/성장 로직 + 테스트**
6. **런 상태 관리** — Zustand 스토어, 퍼머데스 처리
7. **UI 화면 6종** — 로직 완성 후 붙이기
8. **저장/불러오기**
9. **밸런싱 패스** — 시뮬레이션 스크립트로 클리어율 튜닝

> **각 단계마다 커밋.** 특히 4번(전투 엔진)에서 테스트 없이 진행하면 밸런싱 단계에서 무너짐.
