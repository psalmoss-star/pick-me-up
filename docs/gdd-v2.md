## 0. v1이 놓친 것 — 왜 "생각한 인터페이스"가 안 나왔는가

v1은 **평범한 파티 RPG**를 설계했습니다. 그런데 레퍼런스를 보면 이 게임의 정체성은 전투가 아니라 **화면 그 자체**입니다.

| | v1 (잘못됨) | v2 (레퍼런스 기준) |
|---|---|---|
| 플레이어 위치 | 파티를 조종하는 지휘관 | **화면 밖의 '마스터'** — 직접 조종 못 함 |
| UI 성격 | 게임 UI (버튼·카드·탭) | **시스템 창** — 게임이 나에게 말을 건다 |
| 전투 | 내가 스킬 누름 | **관전** — 편성만 하고 지켜봄 |
| 거점 | 없음 | **대기실** — 시설 짓고 영웅 배치 |
| 층 | 그냥 싸움 | **임무 유형**이 층마다 다름 |
| 영웅 소비 | 죽으면 끝 | 죽거나 **합성 제물로 갈아버림** |

**핵심 명제**
> 이 게임의 UI는 "게임 화면"이 아니라 **"가짜 모바일 게임의 화면"** 이다.
> 플레이어는 게임을 하는 게 아니라, **게임을 하는 사람을 연기**한다.

이걸 못 잡으면 아무리 잘 만들어도 "그냥 흔한 방치형"이 됩니다.

## 1. 비주얼 언어 (가장 중요한 섹션)

### 1.1 시스템 창 (System Panel) — 이 게임의 시그니처 컴포넌트

레퍼런스에서 반복되는 그 검은 패널. **모든 정보 전달은 이 컴포넌트를 거친다.**

```
┌═══════════════════════════════┐   ← 장식 코너 (SVG, 4방향)
│  ─────────────────────────    │   ← 이중 헤어라인
│                               │
│     한 이스라트(★) Lv.5       │
│        (Exp 44/50)            │
│   클래스 : 초보자(Novice)      │
│   힘 15/15  지능 15/15        │
│   체력 15/15  민첩 15/15      │
│   보유스킬 : 없음              │
│                               │
│  ─────────────────────────    │
└═══════════════════════════════┘
```

**구현 스펙**
| 속성 | 값 |
|---|---|
| 배경 | `#0a0a0f` → `#1a1424` 다이아몬드 그라디언트 |
| 테두리 발광 | 등급별 색상, `box-shadow: 0 0 24px <색>` |
| 코너 장식 | SVG 4개 (좌상/우상/좌하/우하), 등급별 색상 |
| 폰트 | 명조 계열 (본명조 / Noto Serif KR) — **고딕 쓰면 즉시 망함** |
| 정렬 | **가운데 정렬** (좌측 정렬하면 웹앱처럼 보임) |
| 등장 | 아래→위 슬라이드 + 페이드, 200ms |

```tsx
// components/SystemPanel.tsx — 전 화면에서 재사용
<SystemPanel tone="normal" | "rare" | "warning" | "death">
```

톤 4종:
- `normal` — 흰색 프레임 (일반 안내)
- `rare` — 보라/금색 프레임 (소환, 승급)
- `warning` — 주황 (능력치 감소, 경고)
- `death` — 붉은 X, 채도 제거 (영웅 사망)

### 1.2 영웅 카드 — 타로카드

일반 가챠 게임의 사각 썸네일이 **아니다**. 레퍼런스는 명확히 **타로카드**입니다.

```
┌───────────────┐
│      ◈        │  ← 상단 원형 문장 (등급 상징)
│  ╭─────────╮  │
│  │  일러스트 │  │  ← 세로 2:3.2 비율
│  │         │  │
│  ╰─────────╯  │
│      ★        │  ← 하단 별 (개수 = 등급)
│ ≪ 한 이스라트 ≫│  ← 이름 배너 (꺾쇠 장식)
└───────────────┘
```

등급별 프레임 (색만 바꾸는 게 아니라 **장식 밀도**가 달라져야 함):

| 등급 | 프레임 | 장식 |
|---|---|---|
| ★1 | 무광 회동 | 최소 |
| ★2 | 청동 | 단순 |
| ★3 | 은 | 넝쿨 |
| ★4 | 금 | 넝쿨 + 문양 |
| ★5 | 백금 + 발광 | 풀 장식 + 파티클 |
| ★6 | 흑금 + 강한 발광 | 풀 장식 + 후광 애니메이션 |

### 1.3 색상 토큰

```css
--bg-void:      #050508;  /* 최하단 배경 */
--bg-panel:     #0f0d16;
--bg-panel-hi:  #1c1628;
--line-frame:   #e8e4d9;  /* 시스템 창 프레임 */
--accent-rare:  #b57ce0;  /* 소환/희귀 */
--accent-gold:  #d4af37;  /* 등급/보상 */
--accent-blood: #c1272d;  /* 사망/경고 */
--text-primary: #f0ece2;
--text-dim:     #8a8496;
```

> **금지**: 밝은 배경, 둥근 그림자 카드, 파스텔, 기본 Tailwind 회색 팔레트.
> 이 게임은 **어둡고 장식적이고 약간 불길해야** 합니다.

## 2. 화면 구조 (레퍼런스 반영)

### 2.1 정보 구조

```
대기실 (홈 / 거점)
├─ 소환      → 뽑기
├─ 영웅      → 목록 / 상세 / 합성 / 승급
├─ 시설      → 건설 / 업그레이드 / 인원 배치
├─ 탑        → 층 선택 → 임무 브리핑 → 편성 → 관전 → 결과
└─ 도감·기록
```

### 2.2 대기실 = 메인 화면

v1의 "홈 화면"을 버리고 **부감(top-down) 거점 맵**으로 교체.
레퍼런스의 시설 배치도가 그대로 메인 화면이 됩니다.

```
     ┌─────────────────────────┐
     │   [상단 HUD: 젬 / 골드 / 층수 / 영웅수]  │
     ├─────────────────────────┤
     │                         │
     │    ◯ 거점 부감 맵        │  ← SVG 또는 이미지 + 클릭 영역
     │     · 숙소               │
     │     · 훈련소             │
     │     · 합성소             │
     │     · 연금시설           │
     │     · 공방시설           │
     │     · 무기창고           │
     │     · 광장               │
     │                         │
     ├─────────────────────────┤
     │  [소환][영웅][시설][탑]  │  ← 하단 탭
     └─────────────────────────┘
```

시설 탭 시 **시스템 창**이 올라오며 Lv.1/2/3 업그레이드 카드 표시.

**시설 효과 (MVP 4종만)**

| 시설 | 효과 |
|---|---|
| 숙소 | 층 사이 HP 회복량 결정 (Lv당 +15%) |
| 훈련소 | 비출전 영웅 유휴 경험치 획득 |
| 합성소 | 합성 가능, Lv당 성공률/전승률 상승 |
| 무기창고 | 파티 전체 공격력 +Lv×3% |

### 2.3 소환 화면

레퍼런스: "마스터, 다음 스테이지를 진행하기 전에 동료를 뽑아볼까요?"

**연출 시퀀스 (이걸 대충 하면 게임이 죽습니다)**
```
1. 어두운 화면 + 마법진 회전            (600ms)
2. 빛 기둥 상승 — 등급 힌트 색상         (800ms)
3. ★4↑면 화면 전체 플래시 + 진동         (150ms)
4. 시스템 창: "!★!Super!★!Rare!★!"     (rare 톤)
5. 카드 뒤집기 → 타로카드 등장           (500ms)
6. 이름·등급·클래스 시스템 창 표시
```
스킵 가능하되, **첫 ★5는 스킵 불가.**

### 2.4 탑 / 층

v1의 "그냥 층"을 폐기. **층마다 임무 유형**을 둡니다.

| 임무 유형 | 승리 조건 | 구현 |
|---|---|---|
| 토벌 | 적 전멸 | 기본 |
| 생존 | N턴 버티기 | 승리조건만 교체 |
| 수비 | 오브젝트 HP 사수 | 아군 측 오브젝트 유닛 추가 |
| 호위 | NPC 생존시켜 탈출 | 조종 불가 아군 유닛 |
| 탈출 | N턴 내 이탈 | 턴 제한 + 후퇴 판정 |
| 탈취 | 특정 적 처치 후 이탈 | 우선 타겟 지정 |

> 전투 엔진은 이미 `BattleEvent[]` 기반이라 **승리 조건 함수만 갈아끼우면** 전부 구현됩니다.
> `victoryCondition: (state) => boolean` 하나 추가.

층 진입 전 **임무 브리핑**을 시스템 창으로 표시 — 이게 긴장감의 8할입니다.

### 2.5 전투 화면 — 세로 모드 관전

> **개정 (모바일 우선 결정 이후).**
> 원래 이 절은 "가로 모드, 세로 아님"이었습니다. 프로젝트를 **모바일 세로 우선**으로 확정하면서
> 폐기했습니다. 가로 모드는 모바일에서 기기 회전을 요구해 이탈률이 크고,
> 세로 대치 구도가 방치형/수집형 RPG의 표준입니다.

```
┌─────────────────────────────┐
│ 4층 성문 앞 · 수비   TURN 3/7 │  헤더 = 탑 진행도
│ ▬▬▬▬▬▬▬▬▬░░░░░░░░░░         │  턴 게이지 (생존/수비는 이게 승리 조건)
├─────────────────────────────┤
│    [배경 아트 — Scene]       │
│         👹    👹             │  적 (위, 0.92배 — 원근)
│        ▬▬▬   ▬▬▬            │
│          🚪 성문             │  보호 대상 (중앙)
│         ▬▬▬▬▬               │
│      🗡️   🛡️   ✨           │  아군 (아래, 1.0배)
│     ▬▬▬  ▬▬▬  ▬▬▬           │
├─────────────────────────────┤
│ 카일 — 찢는 일격             │  로그 3줄
│  └ 342 피해 (치명타)         │
├─────────────────────────────┤
│  [집중]  [수호]  [후퇴]      │  개입 — 턴당 1회
├─────────────────────────────┤
│   배속 ×2      건너뛰기       │
└─────────────────────────────┘
```

**전투 중 탑 미니맵을 두지 않습니다.** `floorIndex`는 전투 내내 변하지 않는 값이라
176px 세로를 쓰면서 아무 정보도 주지 않았습니다. 같은 정보가 헤더에 이미 있습니다.
그 자리를 개입 바가 대신합니다 — 죽은 공간이 조작 공간이 됩니다.

**중요**: 마스터는 관전이 기본이고, **턴당 1회 '개입'** 만 가능 (쿨다운 있음).
→ 개입 횟수가 곧 이 게임의 전략적 자원.

**개입 3종** (`src/game/intervention.ts`)

| 개입 | 효과 |
|---|---|
| 집중 | 아군의 단일 대상 공격을 지정한 적에게 몰아준다 (확정) |
| 수호 | 지정 아군에게 방어 상승을 부여해 피해를 줄인다 |
| 후퇴 | 지정 아군을 한 턴 물린다 — 행동도 안 하고 피격도 안 된다 |

**'후퇴'가 핵심입니다.** 죽기 직전의 영웅을 뺄 수 있다면 그 판단이 곧 게임이 됩니다.
개입을 아꼈다가 못 쓰고 잃는 경험이 퍼머데스의 무게를 만듭니다.

> **구현 원칙**: 개입은 전투 중 조작이 아니라 **입력**입니다.
> 개입을 고르면 같은 시드로 전투를 다시 계산해 이어붙입니다.
> 이래야 "같은 시드 + 같은 개입 = 같은 결과"라는 재현성이 유지됩니다.
> UI가 엔진 상태를 직접 건드리면 이 원칙이 깨집니다.

### 2.6 결과 화면

```

   [ 타로카드 확대 표시 ]

   ── 획득 ──
```

## 3. 신규 시스템 (레퍼런스 반영)

### 3.1 합성

> 영웅과 영웅을 합쳐 강화한다. 둘 중 한쪽은 **제물**이 된다.

- 제물 영웅은 **영구 소멸** (퍼머데스와 동일 처리)
- 제물의 등급·레벨에 비례해 경험치/승급 재료 전환
- 동일 등급 합성 시 승급 확률 발생
- **UI에서 "제물"이라는 단어를 그대로 쓸 것.** 순화하면 이 게임이 아님

### 3.2 스탯 체계 변경 — 상한이 있는 스탯

레퍼런스: `힘 : 15/15  지능 : 15/15  체력 : 15/15  민첩 : 15/15`

현재/최대 형식입니다. 즉 **레벨업으로 채우고, 승급으로 상한이 열린다.**

```
힘 15/15  ← 이 등급에서 더 이상 성장 불가 = 승급하라는 신호
```

기존 `Stats`를 변경:
```ts
export interface Attributes {
  str: { current: number; max: number };  // 힘
  int: { current: number; max: number };  // 지능
  vit: { current: number; max: number };  // 체력
  agi: { current: number; max: number };  // 민첩
}
```
전투 스탯(HP/ATK/DEF/SPD)은 이 4개에서 **파생 계산**합니다.

```
HP  = vit × 20 + star × 100
ATK = str × 6 (전사계) 또는 int × 6 (마법계)
DEF = vit × 2 + str × 1
SPD = agi × 3
```

> 이게 v1보다 훨씬 낫습니다. 성장 병목이 화면에 숫자로 보입니다.

### 3.3 클래스

`초보자(Novice)` 처럼 클래스명 표기. 승급 시 클래스가 바뀝니다.
```
초보자 → 견습병 → 정예병 → 기사 → 기사단장 → 영웅
```

### 3.4 즐겨찾기

레퍼런스에 등장. 애착 영웅을 등록하면:
- 합성 제물 선택 시 **경고 확인 1단계 추가**
- 사망 시 결과 화면 연출 강화

→ 플레이어가 스스로 "이 영웅은 소중하다"고 선언하게 만드는 장치. 퍼머데스의 감정 증폭기.

## 4. 수정된 MVP 범위

**넣을 것**
- 대기실 거점 화면 + 시설 4종 (Lv.3까지)
- 소환 (연출 포함)
